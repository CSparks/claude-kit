**Maintainer:** "If you're talking about a merge conflict, the only rule that matters is that you're careful and we don't LOSE code." "That rule sure as fuck didn't come from me." "WE've had to handle merge conflicts LOADS of times. It's pretty fucking standard in GIT. Just _BE_ _FUCKING_ _CAREFUL_"

**Decision:** In every project, git work in the maintainer's checkout (conflicts, restoring drift, stash, reset) is allowed and routine. The one rule: be careful and do not lose code. Before any step that can discard work, save it (stash or a patch file) and say where. No agent refuses a git operation because the checkout is "live". This replaces the base CLAUDE.md line "Never run repo-mutating cleanup in the maintainer's LIVE checkout (KIT-T226) — hand them the command."

**Why:** That line carried no maintainer decision id; it was copied from KIT-T226's antidote list and read as his rule. KIT-T226's real failure was a revert built over uncommitted work with no backup, which this rule covers. Rejected: hand-the-command as a blanket rule; it stalls the bill and protects nothing a backup does not.
