## Description
request-gate.mjs re-fires on the SAME already-routed user message at every subsequent Stop (stiletto 2026-09-04, three times for 'Go for it. I also have this feedback…' after it was promoted to ST-T574/ST-D126/ST-T575/ST-T576 and a [no-capture] token was given). Root cause: the gate keys on the latest user message text and holds no memory that a capture/route or a [no-capture] already answered it. Fix: persist routed message hashes per session (or accept the [no-capture] token once) so a routed request never nags again
