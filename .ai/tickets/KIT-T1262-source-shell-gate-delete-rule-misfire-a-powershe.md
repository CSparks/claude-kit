## Description
source-shell gate (delete rule) misfire: a PowerShell command that read a temp file through the TEMP environment variable, then ran git status --short on a folder, was BLOCKED as a shell command deleting source by hand, reason: a git call outside the allow-list with a PowerShell environment change in the same command. Nothing was deleted or changed: git status is read-only and the environment variable was only read, not assigned. Wanted: reading an environment variable is not an environment change (only an assignment is); read-only git verbs (status, log, diff, show, ls-tree, merge-base, rev-parse) never fall under the delete rule whatever precedes them in the command. Seen in road-generator, main thread, 2026-11-15.

## Notes
Fixed in 3ab6625 (runtime 3ab6625). hooks/lib/git-call-policy.mjs: only an assignment ($env:X =, ${env:X} =, Set/New/Remove-Item on Env:, SetEnvironmentVariable, export) is an environment change; reading $env:TEMP, Get-ChildItem Env: or GetEnvironmentVariable is not. A read-only verb (status, log, diff, show, ls-tree, ls-files, merge-base, rev-parse, rev-list, cat-file, show-ref, describe, shortlog) is exempt from the environment-change rules unless the change names GIT_*, PATH, PAGER, HOME, XDG_CONFIG_HOME or USERPROFILE (those can wrap git itself); an env prefix in front of git still refuses. Tests: hooks/git-call-environment.test.mjs 10 passed (also from the export). hooks/source-shell-gate-discard.test.mjs: the set -a case now uses a writing verb; the machine was too loaded to finish the whole file inside the 170 s limit (an earlier run, 269 passed, failed only that case, which is fixed), so a quiet-machine run of that file is still owed: node hooks/source-shell-gate-discard.test.mjs.
Security review of 3ab6625, three findings, all closed in dcfc12a (runtime dcfc12a). (1) Parser differential: the read-only exemption tested name spellings. Closed: hooks/lib/env-change.mjs parses every change to a literal variable name or null (Env:\ drive path, -Name argument, variable, concatenation, quoting, non-literal SetEnvironmentVariable all parse to null) and git-call-policy exempts a read-only verb only when every change has a literal name on HARMLESS_ENV_NAMES; a null name refuses. (2) EXPORTS narrowing missed assignment forms. Closed: any Env: reference outside Get-Item/Get-ChildItem/Get-Content/Test-Path and gi/gci/ls/dir/gc/cat is a change (so si, ni, ri, cli, rni, cpi, mi, Set-/Add-/Clear-Content, Set-Location, Remove-/Rename-Item refuse); a drive read counts only in a segment with no assignment, grouping or -*Variable parameter and a pipeline ending in a harmless sink (so Get-Item Env:X | Set-Item and ForEach { Set-Item } refuse); a $env: token is a read only when no assignment operator, comma (multiple assignment) or ++/-- follows; [Environment] is a read only as ::GetEnvironmentVariable(s)(. (3) Denylist: removed; HARMLESS_ENV_NAMES ships empty, so nothing is exempt today (the read-only verb exemption of 3ab6625 is, in effect, withdrawn; only the original misfire stays fixed: a plain read of $env:TEMP before git status passes). Known residual, pre-existing and not widened: a drive path built by string concatenation with no literal Env: or $env: in the text. Tests: hooks/git-call-environment.test.mjs 14 checks over every bypass form (each refused) and the misfire (passes), mutation-checked four ways (assignment parse, drive read, sink check, allow-list); hooks/source-shell-gate-discard.test.mjs 264 passed, 0 failed.
Round 3, runtime e70772c: two more review findings (the Environment provider reached without the Env: drive name: Environment::NAME, Microsoft.PowerShell.Core\Environment::, -PSProvider Environment, New-PSDrive; bash declare/typeset/local with several flag groups, quoted or backslashed export, set -k / set -o keyword) were the same disease: enumerating change forms. Closed by INVERSION in hooks/lib/env-change.mjs: a command is no environment change only when every mention of the environment is a known read form; the known reads are blanked ((a) $env:NAME / ${env:NAME} with no assignment operator, comma or ++/-- after it; (b) Get-Item/Get-ChildItem/Get-Content/Test-Path and gi/gci/ls/dir/gc/cat on a literal Env: or Env:NAME in a segment with no assignment, grouping or -*Variable parameter, the pipeline ending in a harmless sink; (c) [Environment]::GetEnvironmentVariable(s)( with literal arguments, no assignment after it; bash $NAME, ${NAME}, printenv NAME and env alone name no mention), quotes, backslashes and backticks are stripped, and any mention left (env:, Environment, PSDrive, PSProvider, export, setenv, declare, typeset, local, set -) before a git word is a change that refuses. No git verb is exempt and the name allow-list is gone. Tests: hooks/git-call-environment.test.mjs, 105 change spellings (the review's, mine, new ones), each refused before every verb and before a later git call; the misfire and the read forms pass; mutation-checked five ways (quote stripping, mention words, assignment parse, pipeline sink, provider mention); hooks/source-shell-gate-discard.test.mjs 264 passed, 0 failed. Read forms agents may use that now refuse: [Environment]::GetFolderPath/NewLine/CurrentDirectory/ExpandEnvironmentVariables, Get-Item Env:$name (a variable name), Get-ChildItem Env: | Where-Object { } or ForEach-Object, and any path or word spelled export, local, declare, typeset, environment or psdrive before a git call (cd src/local && git status). Residual (invisible to any text check): a keyword or drive path assembled at run time.
DECISION (round 4, runtime 8fd94fa): the read exemption is WITHDRAWN and must not be reopened as a parser exercise. Three review rounds (3ab6625, dcfc12a, e70772c) each found real bypasses of the recogniser that decides a command text only READS the environment: a denylist of names; Env:-drive and alias enumeration; then inversion with read-form blanking, broken by an assignment hidden behind a comment or backtick continuation after the variable, names and commands built at run time with iex, Invoke-Expression or eval, a quote-unaware segment split faking a read segment, and over-greedy braced-variable blanking. A text-level read recogniser cannot be made sound, and every refinement loosened a gate that exists to stop one agent git call sweeping another agent files. hooks/lib/env-change.mjs is deleted. The rule is the pre-3ab6625 one (any environment mention before a git word, in the command or a command text it runs, refuses) plus spellings the reviews found that no path or argument contains: declare, typeset or local with any flag group holding x, set -k, set -o keyword, quote, backslash and backtick evasion, Environment::, PSProvider, PSDrive. The original misfire (Get-Content of a path under the TEMP variable, then git status --short crates) is resolved by the message: the refusal now says the environment is named in the same command, naming the token it saw, and tells the caller to run the git call as its own command, with no environment variable read or set in the same command. Regression: hooks/git-call-environment.test.mjs, 116 change spellings each refused before every verb, reads refused, paths and words containing local or environment pass, the message checked end to end through the gate, mutation-checked three ways; hooks/source-shell-gate-discard.test.mjs 264 passed, 0 failed. Known residual, pre-existing: keywords or Env: paths assembled at run time with no literal mention. Live windows: hooks load from the sealed runtime current via compat-run.mjs, so every session on this machine ran a newly published runtime from its next hook call: 3ab6625 from 08:03 to 08:17, dcfc12a 08:17 to 08:29, e70772c 08:29 to 08:39, local time 2026-11-15; no gate decision log was checked for calls those versions passed.
Round 5, runtime 6764a79: three plain tightenings, refuse direction only. (1) set followed by any option, or -o allexport / -o keyword among its arguments, is an environment token. (2) Environment as a word (System.Environment, type references, -as type) is one, case-insensitive, except as a component of a path-like token (docs/environment.md, AppData Local Temp paths). (3) declare, typeset and local as a command word refuse whatever their flags (command word: segment start, after then, do, else, elif, if, while, until, or after a wrapper such as command, builtin, exec, eval, sudo, env, time, nohup, xargs, bash, sh); the x-flag parsing is gone. Tests: hooks/git-call-environment.test.mjs 162 change spellings each refused; paths and words containing local or environment, F=msg.txt; git commit -F with the variable, and a lone git call pass; mutation-checked four ways; hooks/source-shell-gate-discard.test.mjs 264 passed, 0 failed. Finding (4), a keyword or name built at run time by expansion or concatenation, is the RECORDED RESIDUAL and is NOT taken: a text check cannot see it; the gate guards against accidents between cooperating agents, not against deliberate obfuscation; and the proposed rule (the git call must be the only command whenever anything dynamic appears) would refuse ordinary commands such as git commit -F with a message-file variable. This ticket is closed to further rounds: a later review that raises only more spellings of the residual is noted here and does not change the gate.
