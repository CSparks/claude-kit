(bug) q fts crashes on a hyphenated phrase: 'no such column: first' --body Repro: node scripts/q.mjs fts "no ask-first gate" -> 'q: no such column: first'. The phrase is passed to SQLite FTS5 unquoted, so the hyphen splits it and 'first' is parsed as a column reference. Root cause: fts terms are not quoted/escaped before hitting the MATCH expression. Any hyphenated term (very common in ticket titles: 'ask-first', 'low-poly', 'file-length') breaks the query surface the query-gate FORCES agents to use instead of grep. Found from inv4d3rs while grounding a feature request.
