(feature) Build broker — a central testing facilitator (Chris 2026-09-02: split work among agents 'in the best possible way, which means some kind of central testing facilitator to avoid multiple environments'). Design: ONE Node process owns the main checkout + shared CARGO_TARGET_DIR; workers edit in cheap git worktrees on their own branches (no target dir, no cargo), commit, and submit job files {repo: stiletto|rapid-game, branch, commands, land: bool}; the broker serially rebases the branch onto main, switches the build checkout to it, runs the commands (-j 3, --no-fail-fast, logs to files), writes a result file (exit codes + log tails), switches back; land+green → merge to main + push (+ pathspec-only stiletto re-pin for rapid-game jobs); red or rebase conflict → bounce with the log. Workers poll their result file with a bounded until-loop. Buys: one warm build, one writer on main, no index sweeps by construction, N editing agents across efforts, a linear verified merge history. Home: claude-kit scripts/broker/ + a skill for workers (worktree add, submit, wait) + docs; per-project config (repos, submodule pin rule, parallelism).
