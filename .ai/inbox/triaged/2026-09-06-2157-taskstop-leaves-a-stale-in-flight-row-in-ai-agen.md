(bug) TaskStop leaves a stale in-flight row in .ai/agents.jsonl: killing an agent with TaskStop fires no SubagentStop, so the roster keeps showing it as in flight and dispatch-guard blocks the NEXT dispatch in that tree with a phantom conflict. Observed 2026-09-06 in stiletto-2349/rapid-game: agent a99f6e1e91faa2508 was stopped (TaskStop returned success, task-notification reported status killed) and 32 minutes later dispatch-guard still listed it as in flight. ROOT CAUSE: the roster is only closed by the SubagentStop hook, so any termination path that bypasses that hook (TaskStop, and probably a crashed or timed-out agent) never writes a terminal row. FIX SHAPE: close the row on the kill path too - either TaskStop writes a status row itself, or dispatch-guard treats a row with no terminal record and no live task as dead rather than in flight. Workaround used: append a terminal row by hand, which is exactly the kind of manual store surgery the roster exists to avoid.
